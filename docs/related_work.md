# Related work and comparison boundaries

This comparison selects methods that are close to the repository's SF–power learner, delivery/energy objective, or feedback protocol. It is not an exhaustive survey. A feature documented in a paper is distinguished from a feature reproduced in this repository. Published numerical results from different simulators are not treated as directly comparable measurements.

PDF page numbers below count the title page as page 1. Section references are used where a stable HTML article is available. Source access was checked on 17 November 2026.

## Conventional ADR is an implementation-dependent reference

LoRaWAN defines ADR control and `LinkADRReq`/`LinkADRAns`, but this should not be described as a single universally specified server-side optimization algorithm. A comparison called ADR must state its SNR aggregation, history length, margin, update interval, power ordering and fallback rules. See [LoRaWAN L2 1.0.4, Section 5.2](https://lora-alliance.org/wp-content/uploads/2021/11/LoRaWAN-Link-Layer-Specification-v1.0.4.pdf).

If an ADR-style rule is included under the common simulated feedback protocol, it is an **adapted reference**. Its control path is not automatically identical to a production network server issuing standard MAC commands. The same applies to bandit implementations moved to this experiment's 30 SF–power choices and delayed reports.

## What the comparison can establish

The repository separates three questions:

1. Does adding delivery history and/or changing the reward alter the allocation trade-off under matched conditions?
2. Does compact feedback reduce radio cost within the same learner and reporting cadence?
3. Do these effects persist across the declared load, density and feedback-loss cases?

The first two have distinct controls. A comparison that changes state, reward, report size and training simultaneously cannot assign the resulting difference to one ingredient. An operational extension can be useful even when it is not a new learning algorithm.

Compression and aggregation are also established protocol techniques. [RFC 8724, Section 8.3.2.1](https://www.rfc-editor.org/rfc/rfc8724.html#section-8.3.2.1) describes compressed bitmap acknowledgment, and [RFC 9441, Section 3](https://www.rfc-editor.org/rfc/rfc9441.html#section-3) combines several windows in one response. These concern SCHC fragmentation; the project's application report borrows principles and is not a standardized SCHC ACK.

Claims of being the first joint SF/power allocator, the first energy-aware RL method, the first delayed-feedback learner, or the first method tested under congestion are not supported. A universal superiority claim over the studies above would require additional faithful reproductions and validation beyond the current simplified simulator.
